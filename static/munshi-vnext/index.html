Six stages. One chain of evidence.

Observe

Every line of the log keeps its original line number, so anything shown later can be traced back to the exact text.

Oct  1 09:00:00 server01 sshd[1]: Failed password for root from 203.0.113.5 port 22 ssh2

Interpret

OpenSSH “Failed/Accepted password” lines become structured events: time, username, source IP, port, outcome. Lines the parser cannot read are counted as skipped, never dropped silently.

Detect

Failures are grouped per source IP and split by a 15-minute pause. Ten or more failures become a rule match: password spray with 8+ usernames, otherwise brute force. No AI engine, no severity score.

Investigate

Open a finding to see its facts beside the original log lines. An IP address is a network location, not a person, and logins from the same address are context, not proof.

Evaluate

The rules are scored against synthetic logs with planted attacks, including misses and false alarms. These results do not describe performance on real systems.

Chronicle

Findings laid out in time order using only returned timestamps and counts. Observation and interpretation stay separate.
